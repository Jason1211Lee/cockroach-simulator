# 2026-11-18：搜尋倒數不受幀率步長限制

## 本次小目標
修正人類 120 秒搜尋倒數因 Math.min(.04,dt) 而在低幀率變慢的問題。開始前已讀最新根目錄（未見 AGENTS.md）、GAME_PLAN.md、3D 程式與整合測試、未合併 PR；唯一開啟 PR 為 #1，沿用 docs/game-foundation。

## 實作與執行步驟
1. 新增 huntLast 時戳與 syncHunt，以 performance.now／requestAnimationFrame 同一時間來源的毫秒差計算人類活躍時間，與有上限的移動 dt 分開。
2. 在每幀開始先同步倒數，已超時則先結束再進入移動閘門，長時間卡頓後不先移動才失敗。
3. 暫停前同步上一幀到按鈕事件之間的活躍時間；恢復時更新時戳並排除整段暫停時間。失焦沿用既有 setPaused 邏輯。
4. 動作前同步倒數，禁止在截止時間後、下一幀繪製前靠按鍵搶分。重開與選角重建時戳。舊於目前時戳的回呼不讓時鐘倒退。
5. 僅更動人類搜尋倒數；NPC、移動與飛行仍沿用原有模擬步長。

## 完成標準與測試
- node test-page-runtime.mjs：完整整合案例通過，新增 10 FPS 下 119.9 秒未結束／120 秒結束；活躍畫面卡頓 121 秒後先超時且角色不移動；幀間暫停精確計入已過 20ms；無動畫幀的一分鐘暫停不計入；超時後未繪製前動作無法計分；重開使用新時間起點；舊時戳不倒退。
- 既有普通幀率 120 秒邊界、暫停／失焦、勝敗停止、角色切換、追打／毒霧、安全區、遮蔽、搬運與成長等同檔整合案例通過。
- 抽出 HTML module 的 node --check：通過。
- 測試將 mock performance.now 與 mock 動畫幀時戳同步，使用 Node VM 與 DOM／Three.js 替身；時間由測試主動推進，不是真的等待兩分鐘，也不是瀏覽器或手機量測。

## 手動驗收
選人類，對照另一個計時器觀察倒數 → 降低幀率，倒數不應隨移動一起變慢 → 暫停一段時間再恢復，保留原剩餘時間 → 超時後動作不能計分 → 重開回到 120 秒。
